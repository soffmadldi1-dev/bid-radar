# 📡 공고 레이더

조달청 **나라장터 용역 입찰공고**를 매일 아침 7시(한국시간)에 자동으로 수집해서,
내가 정한 키워드에 맞는 공고만 웹페이지로 보여줍니다.

- 내 컴퓨터가 꺼져 있어도 GitHub가 대신 실행합니다.
- 완성된 화면 주소: `https://<내-깃허브-아이디>.github.io/bid-radar/`

## 1. 폴더 구성 (무엇이 무슨 일을 하나요)

| 파일 | 하는 일 |
|------|---------|
| `config.json` | **키워드·제외어를 고치는 파일.** 평소에는 이것만 수정하면 됩니다. |
| `scripts/collect.py` | 나라장터 API를 불러 공고를 모으는 프로그램 |

| `data/status.json` | 마지막 수집이 성공했는지 기록 (자동 생성) |
| `index.html` | 눈에 보이는 웹페이지 |
| `.github/workflows/collect.yml` | 매일 아침 7시에 자동 실행하라는 예약표 |

## 2. 설정 순서 (처음 한 번만, 약 15분)

### 1단계 — 공공데이터포털에서 API 키 신청하기

1. [공공데이터포털](https://www.data.go.kr) 접속 → 회원가입 / 로그인
2. 검색창에 **`나라장터 입찰공고정보`** 입력 → 검색
3. **`조달청_나라장터 입찰공고정보서비스`** 의 **[활용신청]** 버튼 클릭
   - 활용목적: `개인 관심 공고 모니터링` 정도로 적으면 됩니다
   - 상세기능은 전부 체크해도 됩니다
4. 보통 **즉시 승인**됩니다. (간혹 1시간 정도 걸립니다)
5. 승인 후 상단 메뉴 **마이페이지 → 오픈API → 개발계정** 으로 이동
6. 방금 신청한 서비스를 클릭하면 **일반 인증키(Encoding)** 가 보입니다.
   이 긴 문자열을 **복사**해 둡니다.

> ⚠️ 이 키는 비밀번호와 같습니다. 카카오톡·메모장·코드 안에 붙여넣지 마세요.
> 아래 2단계처럼 GitHub Secrets에만 넣습니다.

---

### 2단계 — GitHub에 올리고 Secrets에 키 등록하기

**(1) GitHub 저장소 만들기**

1. [github.com](https://github.com) 로그인 → 오른쪽 위 **＋ → New repository**
2. Repository name: `bid-radar`
3. **Public**(공개)으로 선택 — 무료 계정은 공개여야 GitHub Pages를 쓸 수 있습니다
4. **Create repository** 클릭

**(2) 이 폴더를 저장소에 올리기**

화면에 나오는 안내 중 *"…or push an existing repository from the command line"* 부분을 씁니다.
이 폴더에서 아래를 한 줄씩 실행하세요. (`내-깃허브-아이디` 부분만 본인 것으로 바꿉니다)

```bash
git remote add origin https://github.com/내-깃허브-아이디/bid-radar.git
git branch -M main
git push -u origin main
```

**(3) API 키를 Secrets에 등록**

1. 올린 저장소 페이지에서 **Settings**(설정) 탭 클릭
2. 왼쪽 메뉴 맨 아래 **Secrets and variables → Actions** 클릭
3. 초록색 **New repository secret** 버튼 클릭
4. 입력값
   - **Name**: `SERVICE_KEY`  ← 철자·대문자 그대로 정확히
   - **Secret**: 1단계에서 복사한 인증키 붙여넣기
5. **Add secret** 클릭

> 여기에 넣은 값은 나중에 다시 볼 수 없고, 코드에도 남지 않습니다. 이게 안전한 방식입니다.

---

### 3단계 — GitHub Pages 켜기 (웹페이지 주소 만들기)

1. 저장소의 **Settings** 탭 → 왼쪽 메뉴 **Pages** 클릭
2. **Build and deployment** 의 **Source** 를 **Deploy from a branch** 로 둡니다
3. **Branch** 를 **`main`** / 폴더는 **`/ (root)`** 로 선택 → **Save**
4. 1~2분 기다린 뒤 새로고침하면 위쪽에 주소가 나옵니다

```
https://내-깃허브-아이디.github.io/bid-radar/
```

이 주소를 휴대폰 홈 화면에 추가해 두면 앱처럼 쓸 수 있습니다.

---

### 4단계 — 첫 수집 실행해 보기 (내일 아침까지 안 기다려도 됩니다)

1. 저장소의 **Actions** 탭 클릭
2. (처음이라면 *"I understand my workflows, go ahead and enable them"* 초록 버튼 클릭)
3. 왼쪽 목록에서 **공고 수집** 클릭
4. 오른쪽 **Run workflow** → 다시 **Run workflow** 클릭
5. 1~2분 뒤 ✅ 초록 체크가 뜨면 성공입니다
6. 3단계의 주소로 들어가면 공고 목록이 보입니다

## 3. 평소 사용법

### 키워드 바꾸기

`config.json` 파일을 GitHub 웹에서 바로 고칠 수 있습니다.
(파일 클릭 → 연필 아이콘 ✏️ → 수정 → 아래 **Commit changes**)

```json
"keywords": [
  "취업",
  "관광",
  "직무역량",
  "인재양성",
  "교육훈련",
  "컨설팅"
],

"exclude_keywords": [
  "공사",
  "물품",
  "시스템 구축"
]
```

- **keywords**: 이 중 **하나라도** 공고명에 있으면 가져옵니다
- **exclude_keywords**: 이 중 **하나라도** 있으면 버립니다 (제외어가 우선)
- 단어는 `"큰따옴표"` 로 감싸고, 줄 끝에 `,` 를 붙입니다. **마지막 줄에는 `,` 를 붙이지 않습니다.**
- 띄어쓰기는 무시하고 비교합니다 (`시스템 구축` = `시스템구축`)

바꾼 내용은 **다음 날 아침 수집부터** 반영됩니다.
바로 보고 싶으면 위 4단계처럼 **Actions → 공고 수집 → Run workflow** 를 누르세요.

### 그 밖의 설정 (`config.json`)

| 항목 | 뜻 | 기본값 |
|------|-----|--------|
| `days_back` | 며칠 전 공고까지 훑을지 | `7` (최근 7일) |
| `max_pages` | API를 최대 몇 페이지 읽을지 (1페이지 = 100건) | `20` |
| `keep_closed_days` | 마감된 공고를 며칠 더 보여줄지 | `1` |

### 수집 시각 바꾸기

`.github/workflows/collect.yml` 의 이 줄을 고칩니다.

```yaml
- cron: "0 22 * * *"   # UTC 기준 = 한국시간 오전 7시
```

GitHub는 **세계표준시(UTC)** 를 쓰므로 **원하는 한국시간 − 9시간** 을 적습니다.
예) 한국 오전 9시 → `0 0 * * *` / 한국 오후 6시 → `0 9 * * *`

> 무료 GitHub Actions의 예약 실행은 서버가 붐빌 때 5~30분 늦어질 수 있습니다. 정상입니다.

## 4. 문제가 생겼을 때

| 증상 | 확인할 것 |
|------|-----------|
| 페이지에 "아직 수집된 공고가 없습니다" | Actions에서 **공고 수집** 을 아직 한 번도 실행하지 않았습니다 |
| 노란 ⚠️ 경고 배너가 뜸 | 수집이 실패한 것입니다. 목록은 **마지막 성공 데이터**가 그대로 보입니다. 배너에 적힌 사유를 읽어보세요 |
| `SERVICE_KEY 환경변수가 비어 있습니다` | Secrets 이름이 정확히 `SERVICE_KEY` 인지 확인 (대소문자 구분) |
| `API 키가 이 서비스에 등록되지 않았습니다` | 공공데이터포털에서 **활용신청 승인**이 났는지 확인. 승인 직후 1시간 정도 뒤에 작동하기도 합니다 |
| `오늘 API 호출 한도를 모두 썼습니다` | 하루 한도 초과입니다. 내일 자동으로 다시 시도합니다 |
| 공고가 0건 | 키워드가 너무 좁거나, 최근 7일간 해당 공고가 없는 경우입니다. `days_back` 을 `14` 로 늘려보세요 |
| Actions에 빨간 ❌ | **Actions 탭 → 실패한 실행 클릭 → 빨간 줄** 을 보면 한국어 안내가 적혀 있습니다 |

### 안전장치

수집이 실패해도 `data/notices.json` 은 **절대 덮어쓰지 않습니다.**
따라서 API가 잠시 먹통이어도 페이지에는 어제 데이터가 그대로 보입니다.
